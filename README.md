# QUICK 191AF+ Wi-Fi 测温仪采集系统（Android）

工业平板 App：通过 **MODBUS TCP/IP**（Wi-Fi 局域网，端口 502）采集快克 191AF+ 焊台测温仪的测量结果，自动入库并支持 XLSX 导出。App 为 **TCP 客户端**，仪器为服务端；仪器每次「保存」后由 App 自动收取 **0x1C/0x1D/0x1E**（上传标志/保存温度/判定），操作员**无需在 App 上做任何操作**。

> 协议事实来源：厂方《191AF 系列通讯协议 V1.1》《191AF/192AF 测试仪通讯协议示例 V1.0》
> 可行性分析 / 寄存器表 / 数据可靠性设计 / 验证计划：见 `docs/可行性分析与通讯规格-V1.0.md`
> 数据可靠性优先级：可靠性 > 可维护性 > 简洁性 > UI 美观

## 功能

| 页面 | 功能 |
|---|---|
| 测量 | 实时温度大字显示；OK/NG 全屏弹卡（振动）；线别/机种就地选择；采集事件日志 |
| 记录 | 日期 / 线别 / 机种 / 结果筛选；明细查看（含判定来源）；**导出 XLSX**（系统分享） |
| 配置 | 仪器 IP/端口/单元号/轮询间隔/超时；**配网二维码**生成；配置备份 JSON 导入导出 |
| 管理 | 线别 / 机种维护（历史记录不删除，仅隐藏） |
| 诊断 | 帧级 hex 收发日志（可与厂家报文示例逐字节核对）；手动全读一次 |

后台：前台服务保活（通知常驻）→ 界面退出或崩溃后轮询不中断；采集结果带唯一快照键落库，DB 写入失败时进入 pending 待恢复通道，启动时自动补写 —— **不静默丢数据**。

## 寄存器对照（31 个，0x00–0x1E）

| 地址 | 含义 | 缩放 | 来源 |
|---|---|---|---|
| 0x00 | 实时温度（只读） | **×0.1 ℃** | FACT |
| 0x01 | 温度单位 ℃/℉ | 0/1 | FACT |
| 0x02 | 保存模式 手动/自动 | 0/1 | FACT |
| 0x03 | 自动关机 0/5/10/15 分 | 整数 | FACT |
| 0x0A–0x19 | 设备序列号 ASCII（32 字节） | — | FACT |
| 0x1A | 设定温度（只读） | **×1 ℃** | FACT |
| 0x1B | 误差范围 ±℃ | **×1** | FACT |
| 0x1C | 上传标志（1=有保存；读后清零语义） | 0/1 | 待厂家确认 |
| 0x1D | 保存温度（0x1C=1 时有效） | **×1 ℃** | FACT |
| 0x1E | 判定（0=NG / 1=OK，0x1C=1 时有效） | 0/1 | FACT |

每个轮询周期（默认 1 s）**单次全读 31 个寄存器**，0x1C/0x1D/0x1E 取自同一响应快照，从协议层面消除「读标志后结果才落盘」的丢失窗口。

## 环境与构建

国内网络已适配（阿里云 Maven + 腾讯 Gradle 镜像）：

```bash
# 构建（Debug APK + 单元测试）
./gradlew.bat assembleDebug testDebugUnitTest --no-daemon
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

单元测试用厂家报文示例值验证帧格式与缩放（`app/src/test/java/.../ModbusTcpClientTest.kt`）。

## 装机（平板 Android 10–13）

1. `adb install app/build/outputs/apk/debug/app-debug.apk`（或拷到平板手动安装）
2. 首次启动允许通知权限（前台服务保活需要）
3. 平板连接仪器所在 Wi-Fi 网络

### 首次配置

1. **网络**：仪器出厂配网（快克配网工具/仪器自身界面），或本 App「配置 → 配网二维码」生成扫码配置——注意二维码中的 `ServerIP` 填**仪器自身静态 IP**（App 是 TCP 客户端，主动连仪器）
2. **仪器地址**：配置页填仪器 IP（端口默认 502、单元号 1）
3. **线别/机种**：测量页点击选择即可（或在「管理」页预建）

### 现场操作（操作员）

1. 打开 App → 点「▶ 开始采集」（若配置了开机自动采集则无需）
2. 在仪器上测量并按**仪器上的保存按钮**
3. App 自动收数 → 全屏 OK/NG + 振动 → 自动入库 —— 全程不用碰平板

## 无真机先验证（PC 模拟器）

```bash
python tools/simulate_191af.py 0.0.0.0 502
```

模拟仪器行为：
- `s 351 ok` —— 模拟操作员按保存（351 ℃ / OK）
- `s 351` —— 不带判定时自动判定：|测量−设定| ≤ 误差 ⇒ OK
- `t 233.5` —— 改实时温度；`set <寄存器hex> <值>`、`show`、`q` 等
- 每次收发打印完整 hex 帧（对照 `docs/` 中厂家报文示例）

平板连接方式（二选一）：
- **USB 转发**（推荐，无需同一 Wi-Fi）：`adb reverse tcp:502 tcp:502`，App 仪器 IP 填 `127.0.0.1`
- **同一局域网**：App 仪器 IP 填 PC 局域网 IP（Windows 防火墙需放行 502 入站）

## 导出记录

记录页筛选后点「导出」→ 生成 XLSX → 系统分享（微信/邮件/网盘）。导出文件为纯文本 inline cell，Excel / WPS 可直接打开（方案选型见 doc §11）。

## 诊断与排查

- 测量页右上角虫子图标 → 诊断页：实时帧日志（`→` 发送 / `←` 接收 / `!` 事件），可核对事务 ID、协议 ID、Length、UnitID、功能码
- 采集时仪器地址错误 → 状态栏显示「重连中（第 N 次）」；拔掉仪器会按指数退避重连（最长 30 s）
- 「上传标志」显示 1（新结果）→ App 已同帧收到温度与判定，下轮自动清零
- 若仪器侧出现异常判定与 App 显示不符：以诊断页 hex 帧与仪器实测为准

## 已知边界（待厂家确认）

- **0x1C 读取后自动清零**：按协议语义实现（全读覆盖即清）；若现场实测需「先读后写 0」或延时清零，改 `MeasurementController` 一处即可
- **0x00 实时温度非必要不读**之外的完整寄存器集写入行为未逐一验证；写操作当前 App 不使用（设定温度由仪器面板设置）
- App 不做判定——**判定完全采用仪器 0x1E**，界面标注清晰，避免双重判定口径冲突
- 仪器只保留最近一笔结果；App 端每笔自动落库，历史不丢
