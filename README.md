# QUICK 192AF+ Wi-Fi 测温仪 + 扭力计 采集系统（Android）

工业平板 App，两个互相独立的采集界面：

- **烙铁 192AF+**：通过 **MODBUS TCP/IP**（Wi-Fi 局域网，端口 502）采集快克 192AF+ 焊台测温仪的测量结果；
- **扭力计**：通过 **USB 串口**（FTDI，19200 8N2）接收扭力计主动输出的 ASCII 报文（实测 `+5.40kgf*cm`，无换行符）。

两者都自动入库并支持 XLSX 导出，操作员**无需在 App 上做任何保存操作**。烙铁侧 App 为 **TCP 客户端**，
仪器为服务端，仪器每次「保存」后由 App 自动收取结果。

> 设备型号写作 **192AF+**（用户 2026-09-21 定：界面与文档一律用新名）。早期手册/文档里的 **191AF+** 是同一台设备；
> 备份文件的格式标识 `quik-191af-collector` **保持不变**（改了会让现场既有备份导入失败）。


> 协议事实来源：厂方手册《地址分配》表（`piture/file.webp` 第 2 页，2026-09 用户提供）——**以此表为准**
> ✅ App 寄存器层已按该表实现（v4）：一次全读 `0x00~0x23`（36 个），以 `0x1F` 测试上传标志为触发，结果取 `0x20~0x23`
> ⚠️ 早期「实测清单」与手册不符，根因是**整体错位一格 + 只读到 0x1E 恰好截断在结果块之前**，分析见 `docs` §19
> ⚠️ 厂家《191AF 测温仪 MODBUS 通讯协议 V1.1》PDF 的**地址分配表是旧固件版**（`0x1C` 标志 / `0x1D` 保存温度 / `0x1E` 判定，且**没有**电压·电阻·通道寄存器）—— **不得据它改寄存器**。该文档的**通用扫码指令表也是旧版**（写的是 `TERR` 误差范围）；现在按厂家**新版《扫码配置指令》**发 `TSET` / `TMIN` / `TMAX` / `VMAX` / `RMAX`，无线网络指令（`WifiName` / `ServerIP` …）两版一致（见「组合配置二维码」节）
> 可行性分析 / 数据可靠性设计 / 验证计划：见 `docs/可行性分析与通讯规格-V1.0.md`
> 数据可靠性优先级：可靠性 > 可维护性 > 简洁性 > UI 美观

## 寄存器对照（厂方手册《地址分配》表）

> 事实来源：手册第 2 页地址分配表。**表里没有的项，App 一律不使用、不猜。**

| 地址 | 含义 | 缩放 | 说明 |
|---|---|---|---|
| 0x00 | 实时温度 | ×0.1 ℃ | 持续刷新，不定格 |
| 0x01 | 温度单位 | 0=℃ 1=℉ | — |
| 0x02 | 实时电压 | ×0.1 mV | 67 = 6.7 mV |
| 0x03 | 实时电阻 | ×0.1 Ω | 25 = 2.5 Ω |
| 0x04 | 当前测量通道 | 0=温度 1=漏电压 2=地对地电阻 | — |
| 0x05–0x09 | 备用 | — | — |
| 0x0A–0x19 | 设备信息（扫码写入） | 32 字节 ASCII | 作设备标识用 |
| 0x1A | 设定温度 | ×1 ℃ | — |
| 0x1B | 温度判断下限 | ×1 ℃ | — |
| 0x1C | 温度判断上限 | ×1 ℃ | — |
| 0x1D | 电压判断上限 | ×0.1 mV | 手册默认 20 → 2.0 mV |
| 0x1E | 电阻判断上限 | ×0.1 Ω | 手册默认 20 → 2.0 Ω |
| **0x1F** | **测试上传标志** | 0=无效 1=保存按下 | **★触发；置 1 后约 1 s 自动清零**（实测） |
| **0x20** | **测试保存温度** | ×1 ℃ | 标志=1 时有效 → **测量温度真值**（定格值） |
| **0x21** | **测试保存电压** | ×0.1 mV | 标志=1 时有效 |
| **0x22** | **测试保存电阻** | ×0.1 Ω | 标志=1 时有效 |
| **0x23** | **测试合格判定** | 0=NG 1=OK 2=无效 | 标志=1 时有效 → **结果来源** |

每个轮询周期（默认 **0.9 s**）**单次全读 `0x00~0x23` 共 36 个寄存器** —— 触发标志、定格值、判定天然取自同一响应帧（原子快照）。

轮询是**固定周期**：`nextDelay = 周期 − 本轮已耗时`（不是「读 → delay(周期)」），**并有 200ms 下限**。旧写法实际周期 = 读取耗时 + 周期，Wi-Fi 一抖动就越过 1 s 标志窗口 → 频繁走补收通道 → **多记一笔**（用户 2026-09 反馈的那个 bug）；而下限是必须的 —— 没有它，某轮耗时超过周期时会算出 0，变成**背靠背连发请求、一点喘息都不给链路**（见「偶发断连」一节）。

**触发与去重**（判定逻辑集中在 `collect/SaveTrigger.kt`，纯 JVM、12 例单测守着）：
1. **首帧只建基线**（标志与签名都记），不记录 —— 防把连接前遗留的结果当成新结果。
2. 标志由 0→非 0 → 记录一笔。周期 0.9 s 小于 1 s 窗口，正常情况下必中；若同一笔被**两帧**都读到（窗口跨了两个周期），靠**结果签名**相同跳过，不重复入库。
3. **弹卡期间停止判定与记录**：OK 结果弹出全屏卡（5 s）时，**轮询照常进行**（链路保温），但这几帧**不判定、不入库、不弹卡**；卡收起后的**第一帧只重建基线** —— 卡显示期间仪器上的任何变化都不会被当成本笔结果（用户 2026-09 要求「全屏显示完后再继续读取数据」）。
   > 2026-09-21 修订：原来是「弹卡期间**完全不发请求**」，但那会留出 5 秒静默期 —— 若仪器/AP 的空闲回收短于 5 秒，就会**每保存一笔被踢一次连接**（现场表现正是「断连变频繁」）。**数据行为两种做法完全一致**，区别只是链路是否一直热着。暂停仍有 `HOLD_MAX_MS = 15 s` 上限兜底（界面异常也不会永久不判定）。
4. **补收**：若某轮读到时标志已自清（读晚了：Wi-Fi 抖动、入库耗时），此时结果块内容已变 → 判定为「漏掉的那一笔」并补记，日志标注「（补收）」。判据三重：结果块存在 + 判定值合法（0/1/2）+ **结果签名**变化。固定周期 + 弹卡暂停之后，这条路只剩兜底作用（界面不在测量页时）。
5. **结果签名只含 `0x20~0x23`**（判定 + 保存温度/电压/电阻）—— 即「只有按保存才会写」的四个寄存器。**刻意不含**实时温度/电压/电阻（持续变化）、`0x04` 测量通道与 `0x1A` 设定温度（操作员切通道/改设定时会变）—— 纳入任何一个都会在补收通道上造成与操作不符的重复记录。

**判定与入库规则**：完全采用仪器 `0x23`，App 不参与判定。

| `0x23` | App 行为 |
|---|---|
| `1`（OK） | **入库** + 全屏弹卡 + 振动 + 自动收录设备编号（见下节） |
| `0`（NG）/ `2`（无效） | **不入库、不弹卡、不振动**，诊断日志留一行 `○ NG 不入库：345.0℃（…）` —— 用户 2026-09 定「只保留 OK」。日志留痕是为了不静默 |

**降级**：若仪器固件没有 `0x1F~0x23`，全读会回**异常码 02（非法数据地址）**；App 自动退到 `0x00~0x1E`（31 个）重试并在事件日志明确告警。降级时**读不到判定 → 一笔都不会入库**（宁可不下结论，也不编造一条 OK；早期按 `0x04` 猜判定的兜底已删除），实时温度/电压/电阻仍在界面上正常显示。

## 组合配置二维码（温度 + 漏电压上限 + 接地电阻上限 + 设备编号）

「管理」页新增四类字典，测量页各有一个下拉，旁边一个「配置二维码」按钮：

| 字典 | 输入 | 说明 |
|---|---|---|
| 温度设置 | **只需两个数字**：设定温度 + 误差范围（如 `420` + `20`） | 自动命名 `420±20`（`±` 是 U+00B1，仅用于显示） |
| 漏电压上限 | **只需一个数字**：mV，最多一位小数（如 `2`） | 自动命名 `2 mV`；对应寄存器 `0x1D`（×0.1） |
| 接地电阻上限 | **只需一个数字**：Ω，最多一位小数（如 `2.5`） | 自动命名 `2.5 Ω`；对应寄存器 `0x1E`（×0.1） |
| 设备编号 | 编号字符串 | 带来源标记：「仪器」= 仪器扫码写入后被 App 自动收录；「手输」= 在管理页/测量页手输 |

**二维码格式**（照厂家《扫码配置指令》表 1 通用指令，顺序固定 SN → TSET → TMIN → TMAX → VMAX → RMAX）：

```
SN=QK-HT-001,TSET=350,TMIN=330,TMAX=370,VMAX=2,RMAX=2.5   ← 四项全选
TSET=350,TMIN=330,TMAX=370                                ← 只选温度设置
VMAX=2                                                    ← 只选漏电压上限
RMAX=2                                                    ← 只选接地电阻上限
SN=QK-HT-001                                              ← 只选设备编号
```

**选哪项配哪项**（用户 2026-09 定）：三项配置里**任意一项有选择就能出码**，没选的项**整条不输出**，仪器上那项保持原值不变（不会顺手把温度也改掉）。设备编号是可选的附加项，为空就不含 `SN`。

指令之间用**英文逗号**，字符必须是英文状态（有单测挡着，`±` / `Ω` 绝不会进二维码）。

> ⚠️ **指令集换版（2026-09-21）**：旧文本协议里的 `TERR`（误差范围）**已不再使用**，改为 `TMIN`/`TMAX` 两条。依据是厂家新版指令表与真机寄存器一一对应 —— `TMIN`/`TMAX` = `0x1B`/`0x1C`（温度判断下限/上限）、`VMAX` = `0x1D`、`RMAX` = `0x1E`；而 `TERR` 对应的旧固件里 `0x1B` 存的是单个 ± 值。**尚未真机扫码验证**：扫完在测量页最下方「仪器状态」核对设定 / 温度范围 / 电压上限 / 电阻上限即可。

**两条约定**（用户 2026-09 定）：
1. **保存完一笔数据后「设备编号」选择自动清空**（温度、上限设置像机种一样保留）—— 由控制器清空，界面自动跟随；
2. **设备编号自动学习**：保存数据时把本次用到的编号收进「设备编号」列表 —— 因为编号常常是**在仪器上扫码输入的**，App 主动记下来，下次就能跟温度一起生成二维码，不用再单独配一次。

**记录里存哪个编号？**（用户定：**以仪器扫码写入的为准**）：`0x0A~0x19` 读到的设备信息非空就用它，**仪器里是空白的**才用手选的那个；两者都写进记录原有的 `deviceInfo` 列（表结构未变）。

## 与旧「实测清单」的差异（根因：错位一格 + 读长度截断）

用户早期实测清单与手册表**整体差一格**（他的 26/27/28 = 手册 0x1B/0x1C/0x1D…），且 App 当时只读 `0x00~0x1E`，**恰好停在结果块之前**。于是：

| 旧结论（v3） | 实际 |
|---|---|
| 0x1E = 「结果保存标志」，按下=0x0014、保持后自清 | 0x1E = **电阻判断上限**，手册默认 20 = 0x0014 —— 常量值被当成了变化 |
| 0x04 = 「判定结果，非 0 = OK」 | 0x04 = **当前测量通道**；判定在 **0x23** |
| 0x03 = 自动关机时间 | 0x03 = **实时电阻** |
| 0x1A/0x1B/0x1C/0x1D = 未知/设定温度/下限/上限 | 设定 0x1A、下限 0x1B、上限 0x1C、电压上限 0x1D |
| 保存温度找不到（实时值不定格） | **0x20 测试保存温度**：仪器已定格，直接用 |
| 0x1E 保持多久未知 | 0x1F 读后即清，**无保持期概念** |

App 已按手册表重修（DB v4：`leakageMv` → `measuredVoltageMv`，新增通道/上下限/保存电压/保存电阻，旧库自动迁移）。

## 扭力计（USB 串口）

扭力计通过 **USB** 连平板，测完由**设备主动**把数据发给 App（App 不发指令）。**格式已实测确认**（用户 2026-09-22，串口助手实测）：

| 项 | 实测值 |
|---|---|
| 串口参数 | **19200 bps / 8 数据位 / 2 停止位 / 无校验 / 无流控**（手册 6.2「资料输出」的 ASCII + FTDI VCP 与此一致） |
| 报文 | ASCII `+5.40kgf*cm`（符号 + 2 位小数 + 单位） |
| 换行符 | **没有** —— 串口助手按 ~50 ms 间隔把字节分包显示，报文之间没有 `\r\n` |
| 单位 | `kgf*cm`（设备原样输出，`*` 不改成 `·`：QC 记录跟设备显示一致最不容易出错） |
| 噪声 | 实测数据里会夹 `\x18 \x0E \x0F` 这类非协议字节（用户 2026-09-25 反馈）→ 读循环**只留协议字符**，其余丢弃并计数 |

因此解析**不按行读**：字节攒进缓冲区，用 `(符号)(数字)(单位)` 正则扫（`TorqueParser`），
读数之间靠**内容**区分而不是靠换行；没配成读数的部分留在解析缓冲里，
在**诊断页**原样可见（**不静默丢字节**）。每笔照样存**报文原文 + 逐字节 hex**，格式若再变可回溯重放。

**协议字符白名单**（用户 2026-09-25 定）：读循环只把**可能出现在读数里的字符**送进解析器 ——
数字、字母、`+ - . *`、空格、CR/LF、`·`；其余（含 `\x18 \x0E \x0F`、`0x00`、高位字节）一律当噪声丢掉。
丢掉的**字节数如实计数并在诊断页显示**，所以这不是静默丢数据；诊断页同时保留「滤噪声之前」的逐字节 hex，
要回看设备到底发了什么随时能看。好处是读数不再被夹在中间的噪声切碎（`k\x18\x0E\x0Fgf*cm` 这种
不过滤就整笔认不出来），坏处是「滤掉的到底是不是设备发的文字」只能靠 hex 与 UTF-8 判读那一行确认。

|---|---|
| 测量 | 链路状态 + 监听开关；**线别 / 机种 / 扭矩范围 / 设备信息**四个下拉 + 「扫码录入设备」（后置摄像头）；本组三个**暂存格**（`1/3`、`2/3`、`3/3`）+ 平均值 + **即时判定**；**「重测」按钮**（无密码）；倒计时；上一条已保存记录；缺项的橙色提示条 |
| 记录 | 两个日历 + 关键词 + 判定筛选（全部 / 仅 OK / 仅 NG）+ 四个字典下拉 + 明细 + **导出 XLSX** + **删除（同一个删除密码）** |
| 管理 | 线别 / 机种 / 扭矩范围 / 设备信息 四类字典维护 —— 扭矩范围**填上限 + 下限两个数**、名称自动生成；「设备信息」页签多一个「扫码新增」 |
| 诊断 | FTDI 设备列表（VID/PID/芯片/是否已授权）、链路与字节统计、**波特率切换**（带分频值与实际波特率）、**解析缓冲**（未识别内容 + 丢弃字节数）、**噪声计数**（累计滤除字节数 + 每帧标出滤除量）、**状态头统计**（各状态头出现次数 + 线路状态位含义）、**滤掉字节的严格 UTF-8 判读**、原始字节/操作日志、含/不含状态字节切换 |

> 通信记录（原始字节 / 操作日志）**只在诊断页**，测量页不铺这些 —— 现场操作员看的是数字，调试的人进诊断。

**一次测量组 = 库里一行**（用户 2026-09-22 定稿，取代原来的「每笔一行 + 单独一行平均值」）：

```
第 1 笔 → 暂存(1/3)    第 2 笔 → 暂存(2/3)    第 3 笔 → 暂存(3/3) → 起延时
   ├─ 延时内点「重测」 → 三笔全清，从 1/3 重新开始（无需密码）
   └─ 延时到 且 四项信息齐全 → 自动保存成一行（三笔 + 平均值 + OK/NG）
```

- **延时默认 5 秒**（用户要求，可设定），诊断页可选 3/5/10/15/30 秒，落 `app_setting`；延时内又来第 4 笔 → **忽略 + 页面写明**（不并入本组，也不影响这组照常保存）
- **判定**（用户要求 6）：平均值**先圆整到 2 位小数**，再跟所选扭矩范围的 `[下限, 上限]` 比 —— 在范围内 `OK`，否则 `NG`；边界算 OK（闭区间）。**不编造判定**：范围没有上下限（v8 时代建的旧字典）→ 不保存，提示到管理页补填
- **四项缺一不可**（用户硬要求）：线别/机种/扭矩范围/设备信息少任何一项，**即使测满三次也不保存**。顶部橙色提示条写「三次已测完，但还不能保存！请选择：…」，**缺的那一栏标签变橙加粗带 ⚠**，选上即恢复；三笔仍在暂存里（不会丢），补齐后立刻保存
- **「时间」取第三笔的时刻**（用户拍板）；`rangeMin`/`rangeMax` 是**判定当时的上下限快照** —— 范围字典以后被改了，这条记录仍能自证「当时凭什么判 OK」
- **设备信息 = 电动螺丝机的 ID**（扫码或手输），**保存成功后自动清空** —— 换一把螺丝机不用手动清
- 保存前**不清空暂存**（界面在保存前一刻不会看到空的），保存成功才清

**到数反馈**：收到**单笔** → 只**自动切到扭力计页**（还要接着测第 2、3 笔，不弹卡不振动）；
一组**保存完成** → 切页 + **振动** + 弹卡（OK 绿 / NG 红，显示平均值与三笔）。两个安全阀：
只在**烙铁测量页**时才自动切（人正待在历史/配置/管理/诊断页时不抢）、手动切页后 **5 秒内**不自动切。
扭力计弹卡**不 hold 烙铁控制器**（与烙铁弹卡不同）—— 烙铁照常采集。

**扫码录入设备信息**：用**后置摄像头**离线解码（CameraX + zxing，不依赖 Google 服务）。
扫到的内容按约定抽名字 —— 带 `=` 的厂家指令串（如 `SN=QK-HT-001,TSET=350,TMIN=330`）**只取 `SN` 的值**，
没有 `SN` 就**不新增**（不会把整串指令存成设备名）；不带 `=` 的整串当名字（空白折成单空格、最多 64 字）。

**导出**：`扭力计记录_<时间戳>.xlsx`（与烙铁的导出器**各自一份**，互不依赖），**16 列**（`TorqueXlsxExporter.HEADERS`）：

`ID / 时间 / 线别 / 机种 / 扭矩范围 / 设备信息 / 扭矩下限(kgf*cm) / 扭矩上限(kgf*cm) / 第1次(kgf*cm) / 第2次(kgf*cm) / 第3次(kgf*cm) / 平均扭矩(kgf*cm) / 判断结果 / 参与平均笔数 / 原始报文 / 原始字节(hex)`

一行 = 一组三笔 —— 用户要求 4 的字段（时间 / 线别 / 机种 / 扭矩范围 / 设备信息 / 三次结果 / 平均 / 判断结果）全部在内；
数值固定 **2 位小数**（与设备输出、界面、库内一致），`原始报文` 与 `原始字节(hex)` 把三笔原文都带出。

**配置备份 v6**：扭力计四类字典随配置一起导出/导入，**扭矩范围带上限/下限两个数**。
v5 及更早的备份里没有这两个数 → **保留名称、数值留空**（不编造），管理页标「⚠ 缺上下限」，补填后即可判定。
往返规则写在纯函数 `torqueDictsToJson` / `torqueDictsFromJson` 里，被 `ConfigBackupTorqueTest`（10 例）钉死。

> ⚠️ **USB 驱动是自己写的**：用户拍板用 `usb-serial-for-android`，但该库只发布在 JitPack，
> 本机网络下 JitPack 及国内镜像**全部取不到**（构建期实测，见 docs §24.1）—— 所以自写了一个
> **最小 FTDI 驱动**（`torque/usb/`，只做 FT232R 一族的 19200 8N2 读数据，不做 PL2303/CH34x）。
> 网络恢复后要换回官方库，只需替换 `UsbSerialLink` 与 `FtdiSerialPort` 两个类，上层不动。

**烙铁不受影响**（用户最强调的一条）：烙铁的轮询与保存判定跑在 `MeasurementController` 自己的协程里
（由 Application 持有），页面切换只改一个枚举序号；`MeasureScreen` 里没有 `LaunchedEffect`/`onDispose`，
从不 start/stop 控制器 —— 所以切页、甚至停在扭力计页时，烙铁照常采集照常入库。
（这是代码结构上可核对的结论，真机手感仍需实测。）

## 装机（平板 Android 10–13）

1. `adb install app/build/outputs/apk/debug/app-debug.apk`（或拷到平板手动安装）
2. 首次启动允许通知权限（前台服务保活需要）
3. 平板连接仪器所在 Wi-Fi 网络

### 首次配置

1. **网络**：仪器出厂配网（快克配网工具/仪器自身界面），或本 App「配置 → 配网二维码」生成扫码配置——注意二维码中的 `ServerIP` 填**仪器自身静态 IP**（App 是 TCP 客户端，主动连仪器）
2. **仪器地址**：配置页填仪器 IP（端口默认 502、单元号 1）→ 点「保存通信配置」（会自动记入**通信配置历史**，以后下拉即选）；二维码弹窗里的 ServerIP 与这里**自动保持一致**
3. **线别 / 机种 / 站别**：测量页点击选择即可（或在「管理」页预建）
4. **温度设置**：管理页新增，只输「设定温度 + 误差范围」两个数字（如 420 / 20 → 自动命名 `420±20`）—— 建一次，以后在测量页下拉即选
5. **漏电压上限 / 接地电阻上限**：管理页新增，各只输**一个数字**（单位 mV / Ω，最多一位小数，如 `2` / `2.5`）—— 列表右侧直接显示「扫码后仪器寄存器应该是多少」（`0x1D=20` / `0x1E=25`），扫完就地核对
6. **设备编号**：不用预建。仪器上扫码写入编号后，保存一笔就会**自动收录**进列表（标记「仪器」）；也可以手工预建几个
7. **删除密码**：配置页可改（默认 1234）
8. **扭力计**：USB 线把扭力计插到平板上 → 弹出授权时点「允许」→ 底部切到「扭力计」→ 打开监听（默认已开）→
   在「管理」里预建**线别 / 机种 / 扭矩范围**（扭矩范围要填**上限 + 下限两个数**，只认这两条旧条目会标「⚠ 缺上下限」；
   「设备信息」= 电动螺丝机 ID，可直接扫码新增）→ 在扭力计上测一笔就该看到数字；
   若没数据，进「扭力计 → 诊断」看设备列表有没有识别到（VID 应为 `0403`）、以及配置步骤哪一步是 `✘`
9. **自动保存延时**：默认 5 秒（扭力计 → 诊断页可改 3/5/10/15/30 秒）—— 三笔测完后这么久没有「重测」就自动存

### 现场操作（操作员）

**烙铁**

1. 打开 App → 点「▶ 开始采集」（若配置了开机自动采集则无需）
2. 在仪器上测量并按**仪器上的保存按钮**
3. App 自动收数 → **判定为 OK** 时全屏弹卡 + 振动（这几秒不判定不记录，收起后自动继续）→ 自动入库 —— 全程不用碰平板
4. 仪器判定 NG / 无效的结果**不记录**（只在诊断日志留一行）；要换工艺参数就在测量页选好「温度设置 / 漏电压上限 / 接地电阻上限」再点「配置二维码」给仪器扫（选哪项配哪项）

**扭力计**

1. 底部切「扭力计」→ 四项都选好：**线别 / 机种 / 扭矩范围 / 设备信息**（设备信息 = 电动螺丝机 ID，可扫码）
   —— 少一项就**存不进去**（测满三次也会被拦下，页面会橙色写清缺哪项）
2. 在扭力计上测，**测三次** —— 三个暂存格逐个填上（`1/3` → `2/3` → `3/3`），屏幕上能同时看到平均值与 OK/NG
3. 测完第 3 笔**等几秒**（默认 5 秒）→ 自动保存、振动、弹卡（OK 绿 / NG 红）。**不用碰平板**
4. 若是测错了要重来：点「**重测**」（无需密码）→ 三个暂存格清空，重新从 `1/3` 开始（**必须在延时内点**，超时就已经存进去了）
5. 换一根继续测；换工艺就改上面的下拉。**设备信息保存成功后会自动清空**，换螺丝机时重扫一下即可

## 诊断与排查

- 测量页「诊断」按钮 → 诊断页：实时帧日志（`→` 发送 / `←` 接收 / `!` 事件），可核对事务 ID、协议 ID、Length、UnitID、功能码。**采集事件不再铺在测量页**，看日志进这里
- 采集时仪器地址错误 → 状态栏显示「重连中（第 N 次）」；拔掉仪器会按指数退避重连（最长 30 s）
- **偶发断连怎么读日志**（2026-09 起断线会带上证据）：
  `⚠ 对端断开连接（仪器/AP 主动关闭）（已连接 12 分 34 秒，成功读取 812 帧）：… → 1000ms 后重连（第 1 次）`
  → **连了很久才断 = 环境/仪器侧**（Wi-Fi 抖动、AP 漫游、仪器重启）；**连上几秒就断 = 值得继续查代码**
- **断线统计**（诊断页，自本次启动累计，**不会被帧日志刷掉**）：
  `断线统计（自本次启动）：读超时（仪器未应答） 3 次　对端关闭连接 12 次`
  → 「**读超时**」为主 = 链路/仪器侧（Wi-Fi 抖动、仪器忙）；「**对端关闭**」为主且每段连接都很短 = 被主动踢（检查是否有别的客户端连过仪器、或仪器/AP 的空闲回收）；「**仪器异常应答**」为主 = 协议/寄存器层面（那才可能是 App 的问题）
- **协议级异常不再断线**：仪器回异常应答（如 code 03）只记一行 `⚠ 仪器异常应答 code=3（连续 1 次）：TCP 连接保持，继续读取`，并按**正常周期**重试（不抢跑），连续 5 次才认定链路也坏了。旧版是任何异常都整条重连，这是现场「莫名断连」的主要来源
- **帧日志保留 2000 行**（约 15 分钟，原来的 500 行只有约 4 分钟，断线原因会被收发帧刷掉）；断线**频次**看上面的统计，不看日志
- 配网二维码弹窗会显示本机各接口 IP（热点/Wi-Fi），手机开热点无法手动设 IP 时，用显示的同网段地址给仪器配 ServerIP（弹窗内有一键填入建议 IP）
- 若仪器侧出现异常判定与 App 显示不符：以诊断页 hex 帧与仪器实测为准

## 已知边界

- **`0x1F` 约 1 s 自清（实测）→ 轮询周期是硬约束**：默认 0.9 s，只剩 0.1 s 余量；现场若出现「（补收）」日志频繁，说明周期常常超出窗口，应把轮询周期调小（配置页可改）。补收通道默认开启（`MeasurementController.RECOVER_MISSED_SAVE`）
- **固定周期必须有下限**（`MIN_CYCLE_GAP_MS = 200ms`）：2026-09-20 那版把周期算成「周期 − 本轮耗时」但**没有下限**，某轮超过 900ms 时会算出 0 → 背靠背连发请求。旧写法无论多慢都白给链路一个完整周期的静默，所以这是那一版**唯一会主动加大链路压力**的改动，已修（用户 2026-09-21 反馈「更新后断连更频繁」）
- **NG / 无效不记录是业务规则，不是丢数据**：用户 2026-09 明确要求「只保留 OK」。取舍是**查不到不合格品的历史**——需要留证时以仪器自身的记录为准。App 侧不静默：诊断日志有 `○ NG 不入库` 一行，测量页也写明「只记录判定为 OK 的测量」。想改回「全部记录」，只需在 `MeasurementController` 的触发分支里让 NG 也走 `storeResult`
- **降级模式（读不到 `0x23`）一笔都不入库**：无法确认是否合格时宁可不记，也不编造一条 OK。若真机出现这种情况，界面上会有 `⚠ 仪器未提供结果块…` 告警 —— 此时**应先查固件版本，而不是期待有记录**
- **残余丢失窗口**：① App 刚连上那一刻若正处于标志窗口内，该帧被当基线丢弃；② 两次保存结果**完全相同**（同温度同判定）时，只能靠标志脉冲区分，标志脉冲漏读则无法补收；③ 弹卡显示的 5 s 内若有人在仪器上连按两次保存，卡收起后第一帧只重建基线 → 这两笔都收不到（**用户已知并接受**：卡没消失就不记下一组）
- **全部映射来自手册，尚未逐项真机核验**：尤其 `0x20` 是否为仪器屏幕上的定格温度 —— 真机验证清单见下节
- App 不做判定 —— 判定完全采用仪器 `0x23`（1=OK / 0=NG / 2=无效）
- 仪器只保留最近一笔结果；App 端每笔（OK）自动落库，历史不丢
- **删除记录不可恢复**（密码只防误操作，不是权限系统）：密码是本机哈希校验，忘记后只能清 App 数据（会连配置一起清）
- **记录列表最多显示 20000 条**：超过时列表底部有提示，批量删除也以这 20000 条为口径 —— 请先用日期或筛选缩小范围
- **扭力计报文格式来自串口助手实测**（`+5.40kgf*cm`，无换行符）：按内容扫描而不是按行读。
  **未验证**的是「真机上 USB 链路能不能把这串字节完整读出来」（自写 FTDI 驱动，见下）——
  解析规则本身有 23 例单测钉着，缺的是真机 USB 这一段
- **扭力计 USB 驱动是自己写的最小实现**（原因见上）：只覆盖 FT232R 一族的 `19200 8N2`，不认 PL2303/CH34x/CDC-ACM。
  若真机芯片不是 FT232R 一族（诊断页看 PID，`0x6001`/`0x6002` 之外），分频与模式都要重算
  （芯片已于 2026-09-23 真机确认为 **FT232R / PID 6001**，分频 `0x809C` 与官方库算法逐位一致，波特率这条可以排除）
- **「数据中间有乱码」的定性与处置（2026-09-23/24 定位，2026-09-25 处理，见 docs §26/§27）**：
  `SET_DATA` 的 wValue 原写 `0x0208`（= 8 数据位 + **偶校验** + 1 停止位），而手册写的是
  **8 数据位 + 2 停止位 + 无校验**，正确值是 `0x1008`（停止位在 11–13 位）——这一处是**确定的错**，已修。
  剩下那点 `\x18 \x0E \x0F` 按用户 2026-09-25 的决定**不再追根**：读数才是有用数据，其余当噪声——
  读循环加**协议字符白名单**，噪声进不了解析器，滤掉多少字节如实计数并在诊断页显示；
  每帧仍保留「滤噪声之前」的逐字节 hex（回看用）。**剩下的未知**：这些字节究竟是链路采样产生的，
  还是设备本身就在发非协议内容 —— 两种情况的界面表现一样，要区分只能看诊断页那行 UTF-8 判读
- **扭力计的 OK/NG 由 App 判**（与烙铁相反）：平均值落在所选范围内 → OK，否则 NG。这是**业务规则**（用户要求 6），
  不是设备给的判定 —— 所以 **NG 也照样入库**（不合格品也要留证，这一点与烙铁「只保留 OK」不同）
- **一行 = 一组三笔，未保存的组在库里不存在**：三笔只在内存暂存，收满 + 延时到 + 四项齐全才落库。
  代价是「正在测的这一组」重启 App 会丢（未保存的本来就不是记录），**已保存的一条都不会少**
- **延时内没点「重测」就已经存进去了**：超时即落库，此时要作废只能到记录页删（同一个删除密码）
- **底部切换条的导航栏内边距**（2026-09-22 修，用户要求 1）：`MainActivity` 开了 `enableEdgeToEdge()`，
  切换条原来与内容区并排、谁都没吃导航栏内边距 → 在平板上被系统导航栏压住（用户反馈「太矮了、跟导航按钮重叠」）。
  现在**谁在最下面谁负责导航栏内边距**：切换条自己 `navigationBarsPadding()`（高 88 dp + 导航栏高度），
  内容区在有切换条的页面不再重复加。**平板上的实际观感仍需真机看一眼**
- **「切页时烙铁通信不断」是代码结构结论，不是真机实测结论**（见上「扭力计」一节）
- 数据库 v9：`torque_record` 改成**一组一行**（`v1`/`v2`/`v3`/`average`/`judge`/`rangeMin`/`rangeMax`），
  `torque_dict` 新增 `minValue`/`maxValue`（v8 旧库自动迁移：按 `sessionId` 聚合，三个单笔还原到 `v1/v2/v3`、
  平均行还原到 `average`；**判据旧数据里没有 → 上下限留 NULL、判定留空显示「未判定」，不编造**；
  旧结构的原始报文只留得下一笔，所以 v8 迁过来的记录的 `原始报文` 列**不如新记录完整**）。
  旧字典的上下限同样留空 → 管理页标「⚠ 缺上下限」等操作员补填。**不动烙铁任何一张表**
- 数据库 v8：新增 `torque_dict`（扭力计四类字典）与 `torque_record`（扭力计记录）两张表（v7 旧库自动迁移，**不动烙铁任何一张表**）
- 数据库 v7：新增 `limit_preset`（漏电压上限 / 接地电阻上限）字典表（v6 旧库自动迁移，不动 `measurement_record`）
- 数据库 v6：新增 `temp_preset`（温度设置）与 `device_sn`（设备编号）两张字典表（v5 旧库自动迁移，不动 `measurement_record`）
- 数据库 v5：新增 `station` 表 + `measurement_record.stationName`（v4 旧库自动迁移，旧记录站别为空）
- 数据库 v4 起按手册字段重建（v3 旧库自动迁移：`漏地电压` → `保存电压`，新增通道/上下限/保存电压/保存电阻列）

### 真机验证清单（首次连真机时逐条核对）

1. 诊断页点「手动全读一次」→ 看帧长是否为 `0x24`（36 个）而非 `0x1F`（31 个）；若降级会有 `⚠` 事件
2. 不按保存时：`0x1F` 应为 0，`0x20~0x23` 内容无关紧要（手册标注「标志=1 时有效」）
3. 在仪器上测量并**按下保存**，**立刻**再点手动全读：`0x1F` 应为 1，`0x20` 应≈仪器屏幕定格的测量温度，`0x21/0x22` 应为定格电压/电阻，`0x23` 应为 1/0/2
4. 隔 1 秒以上再点一次全读：`0x1F` 应已回 0（验证「约 1 s 自清」；若仍为 1，说明该固件不清零 → App 靠结果签名去重，功能仍正常）
5. 连续测两笔（期间不碰 App），看记录页是否**每笔一条**、有无重复或「（补收）」告警
6. 面板「当前温度」随仪器实时变化；「通道/实时电压/实时电阻」与仪器屏幕一致
7. **只保留 OK**：`s 300 ng` 或仪器上故意测一笔不合格 → 记录页**不应**多出这一条，诊断页应有 `○ NG 不入库：…`
8. **弹卡暂停**：OK 弹卡出现后立刻在仪器上再按一次保存 → 弹卡收起（5 s）后**不应**多出这一条；再正常测一笔应正常入库
9. **组合配置二维码**（**优先做这条** —— 它决定指令集换版判断是对是错）：测量页选温度设置 + 漏电压上限 + 接地电阻上限（+ 设备编号）→「配置二维码」→ 用仪器扫 → 回到诊断页看
   - `0x1A` 是否 = `TSET`（如 350）
   - `0x1B` / `0x1C` 是否 = `TSET ∓ 误差`（如 330 / 370）
   - `0x1D` / `0x1E` 是否 = **界面提示的那个数**（`2 mV` → 应为 `20`；若为 `2` 说明二维码发的是寄存器原值，见 docs §23.4）
   - `0x0A~0x19` 是否写入了 SN
   - 若 `0x1B/0x1C` 没变 → 说明该退回旧指令 `TERR`（docs §23.1）
10. **设备编号自动收录**：仪器上扫码写入编号 → 保存一笔 OK → 「管理 → 设备编号」应出现该编号且标记「仪器」；同时测量页的「设备编号」下拉应已被**清空**
11. **首次启动迁移**：装到已有旧数据的平板上，记录页应仍能打开（DB v8 → v9 迁移：`torque_dict` 加两列、
    `torque_record` 聚合成一组一行；烙铁的记录与配置应**一条不少**，扭力计旧记录应**每组一行**且标「未判定」）
12. **切换界面时烙铁通信不断**（用户最强调的一条）：采集开着 → 切到扭力计页停一会儿 → 切回烙铁页，诊断页的**断线统计不应增加**、帧日志应**连续无缺口**
13. **底部切换条不再被导航栏压住**（用户要求 1）：平板上（尤其带手势条/三键导航的）看底部那条「烙铁 / 扭力计」是否完整可见、能正常点到

### 扭力计真机验证清单（格式已实测确认，逐条核对的是 USB 这一段）

1. **先看设备识别**：「扭力计 → 诊断」设备列表里 VID 应为 `0403`（FTDI）；芯片名若**不是** FT232R 一族（看 PID），
   分频公式要改（`FtdiBaud`，另有 FT232H/FT2232H/FT4232H 的 12 MHz 分支要补）
2. **看配置步骤**：诊断页的逐步日志应**全是 `✔`**；哪一个 `✘` 就说明那一步没被芯片接受
3. **看有没有字节进来**：插上扭力计、在它上面测一笔 → 诊断页「累计字节」应增长；若一直是 0，
   把「含状态字节」打开看有没有数据（有数据但解析不出 = 剥字节或波特率口径有问题）
4. **核对波特率**：诊断页「实际达成」应 ≈ 19200（分频 `0x809C` 是**精确**的，已与官方库算法逐位核对）。
   噪声已由白名单在读取层滤掉（2026-09-25），所以**别再盯着读数那行**，要看这三处：
   - **状态头统计**：只有一种值（如 `01 60 ×N`）→ 链路安静；出现好几种 → 芯片在报线路状态变化；
   - **噪声计数**（解析缓冲那行的「已滤除噪声 N 字节」，以及每帧后面的「滤除 N 字节」）：
     长期为 0 最好；一直涨说明链路上持续有非协议字节，那时才需要回到波特率 / `DATA_8N2` 上找原因；
   - **滤掉字节按 UTF-8 看**：若能把滤掉的那段解成正常文字 → 那是**设备自己发的文字**（不是链路坏字节），
     读数照常解析就不用管它；解不出来才是真乱码
   - **确认 8N2 生效**（2026-09-23 修）：操作日志里「数据位 8 + 停止位 2 + 无校验」那一步必须是 `✔`；
     这条以前写错了位域（配成了偶校验 + 1 停止位，见 docs §26.4 的可能 A），修完若噪声消失即印证
5. **核对读数**：在扭力计上测一笔，页面暂存格应显示**与扭力计屏幕一致**的数（如 `5.40`）；
   若不显示，看诊断页「解析缓冲」里的原始内容是不是 `+5.40kgf*cm` 这个形状（可能多/少空格，或单位写法不同）
6. **一次测量组**：连测三笔 → 三个暂存格依次填上 → 等 5 秒 → 记录页应**多出一行**（不是 4 行），
   行内写着三笔 + 平均 + OK/NG，且弹卡颜色与判定一致
7. **重测**：测两笔后点「重测」→ 三个格清空；再测三笔应能正常保存（前两笔**不该**混进这一组）
8. **四项拦截**（用户硬要求）：故意留一项不选 → 测满三笔 → **不应**保存，顶部应出现橙色提示条、
   缺的那栏标签变橙加粗；把缺的选上 → **立刻**保存
9. **设备信息清空**：保存成功后「设备信息」下拉应已**自动清空**（其余三项保持不变）
10. **第 4 笔**：三笔测完、5 秒内再测一笔 → 页面应写明「已忽略」，这一组仍按原三笔保存
11. **判定**：把扭矩范围设成明显不含平均值的区间 → 应判 NG 并存进记录（**NG 也入库**，与烙铁相反）
12. **自动切页**：停在烙铁测量页时在扭力计上测一笔 → 应**自动切到扭力计页**；
    手动切回烙铁页后 **5 秒内**再测 → 不该被抢走（5 秒后才会自动切）
13. **导出**：记录页导出 XLSX → 表头应为 16 列、一行一组、`判断结果` 列与页面一致
